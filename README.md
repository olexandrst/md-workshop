# Голосування на воркшопі

Веб-застосунок для оцінювання ідей ІТ-рішень під час воркшопу в реальному часі.
Учасники сканують QR-код з екрана проєктора, вводять ім'я та компанію і з телефона оцінюють ідеї.
Ведучий бачить на великому екрані бали, розподіл оцінок і хто як проголосував. Усе оновлюється автоматично.

**Стек:** Python 3.13 · Flask · SQLAlchemy · PostgreSQL (локально можна SQLite) · vanilla JS без збірки · gunicorn / waitress.

---

## Можливості

**Учасник (телефон, без логіна та реєстрації)**
- вводить ім'я та компанію, після чого одразу голосує;
- бачить ідеї з описом і бізнес-ефектами (**нові ідеї — зверху**, щойно додані позначені «Нова») та ставить оцінку за шкалою:

  | Бал | Значення |
  |---|---|
  | 0 | Не релевантно |
  | 1 | Потенційно цікаво |
  | 2 | Актуально і потрібно |
  | 3 | Готові пропрацьовувати концепцію |
  | 5 | Готові пілотувати |

- може змінити оцінку будь-коли; повторне натискання на ту саму оцінку знімає її;
- бачить живі результати під кожною ідеєю: бали, середню оцінку зірочками, розподіл (ведучий може їх приховати);
- з іншого пристрою з тим самим ім'ям і компанією потрапляє до своїх голосів.

**Ведучий (екран для проєктора, `/admin`)**
- **плитки 3×2: на Full HD одночасно видно 6 ідей**, решта — прокруткою;
- на плитці: середня оцінка **зірочками** (з частковим заповненням) і числом, сума балів, кількість голосів
  та гістограма «★★★★★ Пілот — 6 · Компанія (Ім'я), …» — бали 0/1/2/3/5 = кількість зірок;
- **за порядком** (за замовчуванням, нові ідеї зверху) або **за рейтингом** — з анімацією перестановок;
  медалі 🥇🥈🥉 для топ-3, бейдж «Нова» для щойно доданих;
- **клік по плитці — ідея на весь екран** (spotlight): опис, ефекти, великі зірки, усі імена; `←`/`→` — гортання, `Esc` — закрити;
- QR-код у шапці (клік або клавіша `Q` — QR на весь екран);
- додавання, редагування, видалення ідей і зміна їхнього порядку; кожна ідея має один або кілька бізнес-ефектів;
- редагування назви та пояснення воркшопу;
- перемикачі: голосування відкрите/закрите, результати на телефонах, імена на екрані;
- список учасників з можливістю видалити зайвих; скидання голосів після репетиції;
- **експорт в Excel**: підсумок з рейтингом, усі голоси, учасники;
- режим презентації (`P`) ховає кнопки керування, режим на весь екран (`F`), світла/темна тема.

## Сценарій на воркшопі

1. **Заздалегідь:** увійдіть в адмінку (логін `mid`, пароль `digital`), відредагуйте назву воркшопу та ідеї.
2. **Репетиція:** проголосуйте з кількох телефонів, перевірте екран.
   Потім **Налаштування → Видалити всіх учасників** (ідеї залишаються).
3. **На початку:** відкрийте `/admin` на ноутбуці, підключеному до проєктора, натисніть `F` (на весь екран) і `Q` (великий QR).
4. **Під час:** учасники голосують, екран оновлюється кожні ~1,5 с. `P` ховає кнопки керування.
   Обговорюючи ідею, клікніть її плитку — вона відкриється на весь екран з усіма деталями.
5. **Фінал:** «Закрити голосування» фіксує результати. **Експорт Excel** — для звіту та follow-up з компаніями,
   які готові пілотувати.

## Локальний запуск на ПК

### Варіант 1. Швидко, без Postgres (Windows / macOS / Linux)

Потрібен Python 3.11+.

```bash
python -m venv .venv
# Windows:      .venv\Scripts\activate
# macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # Windows: copy .env.example .env
python run.py
```

- Екран ведучого: <http://localhost:5000/admin> — логін `mid`, пароль `digital` (змінюються в `.env`).
- Дані зберігаються в SQLite-файлі `instance/workshop.db`.
- Сервер слухає всю локальну мережу. QR-код автоматично веде на IP вашого ПК, тож телефони в тій самій Wi-Fi мережі
  відкривають сторінку без додаткових налаштувань.
  У Windows під час першого запуску дозвольте Python доступ до мережі у вікні брандмауера.

### Варіант 2. Docker Compose з PostgreSQL

```bash
docker compose up --build
```

- Екран ведучого: <http://localhost:8000/admin>.
- У Docker застосунок не знає IP вашого ПК, тому для телефонів задайте його у `.env`:
  `PUBLIC_URL=http://192.168.1.25:8000`.
  Інший варіант — відкрийте екран ведучого одразу за IP-адресою.
  Якщо QR веде на localhost, екран ведучого покаже попередження.
- Postgres також доступний на `localhost:5432` (користувач, пароль і база — `workshop`).

### Варіант 3. Власний PostgreSQL

У `.env` вкажіть `DATABASE_URL=postgresql://user:password@localhost:5432/workshop` і запустіть `python run.py`.
Таблиці та стартові дані створюються автоматично.

> **Коли зал без надійного Wi-Fi:** розгорніть на Render (нижче), тоді учасники заходять через мобільний інтернет.

## Розгортання на Render

У репозиторії є Blueprint `render.yaml`, який створює:
- веб-сервіс `md-workshop` (Python, план **Starter**, регіон Frankfurt);
- керовану базу **PostgreSQL** `md-workshop-db` (план **Basic 256 MB**, доступна лише всередині Render).

**Кроки:**
1. Render Dashboard → **New → Blueprint** → підключіть GitHub-репозиторій `md-workshop`.
2. Render покаже ресурси з `render.yaml`. Вхід ведучого — логін `mid`, пароль `digital`
   (за потреби змініть `ADMIN_USERNAME` / `ADMIN_PASSWORD` у розділі Environment сервісу).
3. **Apply.** Через 2–4 хвилини сервіс буде доступний на `https://md-workshop-XXXX.onrender.com`.
   Таблиці та демо-ідеї створюються автоматично під час першого старту.
4. Кожен push у гілку, підключену до Blueprint, автоматично перерозгортає сервіс. Дані в базі зберігаються.

`SECRET_KEY` генерується автоматично, `DATABASE_URL` підставляється з бази.
QR-код автоматично використовує публічну https-адресу сервісу.

> Плани можна змінити в Dashboard або в `render.yaml`. На безкоштовному плані сервіс засинає після ~15 хв простою,
> а безкоштовна база видаляється через 30 днів. Для воркшопу закладено платні Starter + Basic.

## Налаштування (змінні оточення)

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `ADMIN_USERNAME` | `mid` | Логін ведучого. |
| `ADMIN_PASSWORD` | `digital` | Пароль ведучого. Зміна логіна чи пароля автоматично завершує всі адмін-сесії. |
| `DATABASE_URL` | SQLite `instance/workshop.db` | PostgreSQL: `postgresql://…` або `postgres://…`. |
| `SECRET_KEY` | генерується в `instance/secret_key` | Підпис cookie-сесій. На сервері задавайте явно. |
| `PUBLIC_URL` | визначається автоматично | Адреса, яку кодує QR (тунель, Docker, власний домен). |
| `SEED_DEMO` | `true` | Додати демо-ідеї для меблевого бізнесу при створенні **нової** бази. |
| `PORT` | `5000` (run.py) / `8000` (gunicorn) | Порт сервера. |
| `WEB_CONCURRENCY`, `GUNICORN_THREADS` | `2`, `8` | Процеси та потоки gunicorn. |
| `SESSION_COOKIE_SECURE` | `true` на Render | Cookie лише через HTTPS. |

**Службові команди:**

```bash
flask --app wsgi init-db          # створити таблиці (безпечно запускати повторно)
flask --app wsgi seed-demo        # додати демо-ідеї
flask --app wsgi reset-votes      # видалити всі голоси
```

## Технічні рішення

- **Реальний час через опитування з версіонуванням.** У записі воркшопу є лічильник `version`, який зростає при
  кожній зміні в тій самій транзакції. Клієнти опитують сервер з `?v=<версія>` (екран кожні 1,5 с, телефони кожні 3 с).
  Поки нічого не змінилось, відповідь займає кілька байтів. Такий підхід надійно працює за будь-якими проксі
  та на Render без WebSocket і sticky-сесій, а у фоні вкладки опитування ставиться на паузу.
- **Цілісність голосів:** унікальність `(учасник, ідея)` та `CHECK score IN (0,1,2,3,5)` на рівні БД.
  Записи серіалізуються блокуванням рядка воркшопу, тож подвійні натискання не створюють дублікатів.
- **Ідентичність учасника:** підписана cookie-сесія без паролів.
  Ім'я та компанія нормалізуються (регістр, пробіли), тому повторний вхід з іншого пристрою повертає до своїх голосів.
- **Приватність:** публічне API віддає лише агреговані результати. Хто як голосував бачить тільки ведучий.
- **Ініціалізація БД** відбувається один раз у майстер-процесі gunicorn під `pg_advisory_lock`,
  тож паралельні старти безпечні.
- **Палітра шкали** перевірена на розрізнюваність: 0 — нейтральний сірий («немає інтересу»), 1→2→3→5 — один синій
  відтінок від світлого до насиченого, окремо підібраний для темної теми.

## Тести

```bash
pip install -r requirements-dev.txt
pytest                                                                     # SQLite
TEST_DATABASE_URL=postgresql://user:pass@localhost/workshop_test pytest    # PostgreSQL
```

GitHub Actions (`.github/workflows/tests.yml`) запускає тести на PostgreSQL 16 при кожному push і PR.

## Структура

```
app/
  __init__.py        фабрика застосунку, обробка помилок
  config.py          конфігурація з env / .env
  models.py          Workshop, Idea, BusinessEffect, Participant, Vote; шкала оцінок
  services.py        бізнес-логіка: голосування, агрегація, рейтинг, стан для клієнтів
  routes_public.py   сторінка учасника, API голосування, QR, healthcheck
  routes_admin.py    вхід ведучого, екран для проєктора, API керування, експорт
  export.py          Excel-звіт
  seed.py            демо-ідеї для меблевого бізнесу
  cli.py             init-db / seed-demo / reset-votes
  templates/         Jinja-шаблони
  static/            CSS та JS (без збірки)
tests/               pytest
run.py               локальний запуск (waitress)
wsgi.py, gunicorn.conf.py   продакшн-запуск
render.yaml          Render Blueprint
Dockerfile, docker-compose.yml
```
